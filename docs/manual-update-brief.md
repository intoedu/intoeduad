## 1. 목적과 작업 규칙

### 목적
매뉴얼은 지금 "구글폼 신청 → 계좌 입금 → 드라이브·구글 시트 기록"을 전제로 쓰여 있다. 실제 업무는 행정 웹앱으로 옮겨졌으므로, 직원이 카드를 보고 그대로 행동했을 때 웹앱의 화면·순서와 어긋나지 않게 고친다. 학부모·원장님에게 나가는 대응 메시지가 웹앱이 보내는 안내(신청 완료 화면, 신청 내용 확인 링크, 알림톡)와 같은 말을 하게 하는 것이 핵심이다.

### 작업 규칙 (반드시 지킴)
1. **기존 형식 유지**: 매뉴얼마다 머리 정보(버전·관리·작성 담당·근거 자료) → 01 한눈에 보기 → 본문 → 상황별 대응 카드 → 확인 필요 항목(담당자 질문지) → 변경 이력 순서를 지킨다. 카드는 "이런 말이 들어오면 / 담당 · 회신 / 대응 메시지 / 하면 안 되는 말 / 넘기는 기준 / 근거 / 후속 · 기록" 칸을 그대로 쓴다(01번 7장).
2. **표시 유지**: `[확인 필요]` `[개선 필요]` `[제안]` `[추정]`을 그대로 쓴다. 웹앱으로 해결된 `[개선 필요]`는 지우지 말고 "웹앱 반영"을 적은 뒤, 실제 운영 시작이 확인되면 지운다(Q15).
3. **역할명만**: 카드·본문에는 사람 이름 대신 00 조직도의 역할명(대표, 행정팀장, 행정 직원, 미국 본부장, 필리핀팀 담당 등)만 쓴다. 사람 이름은 00번 3장 표에서만 관리한다. 웹앱의 역할은 "관리자 / 직원 / 현지 팀(열람)"으로 따로 표기한다(매뉴얼 역할명과 섞지 않는다).
4. **종교 관련 표현 금지**: 새로 쓰는 문장에 넣지 않는다. 기존 원문에 있는 표현은 3장의 해당 항목대로 처리하고, 고유명사(프로그램명·학교명)는 Q18 답이 오기 전에는 바꾸지 않는다.
5. **브랜드명**: "인투유학"만 쓴다("인투유학원", "INTO유학센터" 금지 — 01번 2장).
6. **확인 안 된 것은 `[확인 필요]`**: 웹앱이 정한 값이라도 대표가 확정하지 않은 운영 규칙(5장 질문 대상)은 "웹앱 적용값: ○○ [확인 필요: 대표 확정]" 형식으로 쓴다.
7. **알림톡 표현**: 웹앱 알림톡 4종은 카카오 심사 전이다. "자동으로 알림톡이 갑니다"라고 단정하지 말고 "알림톡(승인 후)으로 1회 안내되며, 승인 전에는 담당자가 카톡으로 직접 보냅니다 [확인 필요: 알림톡 승인일]"로 쓴다(Q13).
8. **웹앱 화면 표기 방식**: 「메뉴 > 화면 > 버튼」 형식으로 쓰고, 메뉴·버튼 이름은 아래 2-1 표의 표기를 글자 그대로 쓴다. 예: 「등록생 > 학생 상세 > 납부 > 정정 안내 보내기」.
9. **버전·변경 이력**: 고친 매뉴얼은 버전을 1 올리고(v1 → v2), 머리 정보의 버전·날짜와 변경 이력 표를 함께 고친다. 변경 이력 문구 예: "행정 웹앱 반영 — 구글폼 신청을 웹앱 신청서로, 개인 서류 보관을 웹앱 업로드·자동 파기로 변경, 카드 ○○ 수정·○○ 추가". 처음 화면(home)의 매뉴얼 카드 버전·카드 수·기준일과 부록 인덱스도 같이 고친다.
10. **원본을 고친다** `[추정]`: 사이트는 빌드된 HTML(`assets/js/search-index.js` 포함)이다. 원본(저장소 `intoedu/intoedu-manual`의 원고 또는 docx)을 찾아 고치고 다시 빌드한다. 빌드 HTML만 손으로 고치면 검색 색인과 어긋난다.
